## Local editing

Run `npm run studio` and open `http://127.0.0.1:5174/studio`. Select **คู่มือเมืองและอาหาร**, then a city and one of the five languages. The editor covers the introduction, three neighborhood/stay areas, three daily plans and weather alternatives, airport code/steps/fare notes, the existing itemized budget, food introduction/vegetarian notes and three food stops with meal allowances. Source names, HTTPS links and map search queries are editable alongside the relevant section. A daily source can be added where one does not already exist.

- State drafts remain in `.studio/draft.json`; city drafts use `.studio/city-draft.json`. Both files are ignored by Git. Switching modes preserves unsaved work in both editors.
- **บันทึกฉบับร่างเมือง** writes only the city draft. **เผยแพร่คู่มือเมือง** writes `content/city-guides.json` and its matching draft; it does not publish the website. Build, commit and push remain separate steps.
- Revisions include the published file and its draft. Another window or a direct file edit makes an older save fail with a conflict rather than overwrite it. Reloading with unsaved changes asks before replacing those changes.
- Missing text, unfinished review dates and blank sources can be kept in a draft. Publication requires complete five-language content, valid review dates with the next review later than the last check, ordered food allowances and safe HTTPS sources. Invalid shapes, unsafe URLs and negative/invalid money values are rejected at the API boundary.
- Main-city and food review dates and language flags are independent. Text edits clear the relevant language flag; changes to shared facts such as budget amounts and source links clear all five flags in that section. Dates are never automatically stamped as reviewed.
- Preview uses the real `CityGuide` component without its create-trip action. It does not write traveler storage. Shared interface labels in `copy` remain file-only; park and preparation editors remain file-only as well.

The Studio keeps its existing localhost/same-origin/session-token protections. Production has no content-writing API. `check:content` now also uses the city validator shared with the API.

## Public preview

The native 1–3 day selector and the existing trip generator are retained. Each day now shows the activity total, buffer total and their combined planned minutes. These are calculated through the planner's existing `dayTimeline` helper. They exclude gaps between morning, afternoon and evening periods and do not claim a measured driving time.

Visit and meal descriptions are visible in the preview, along with the day's weather alternative. A brief introduction explains the draft; the longer notes remain available in a native disclosure. Headings, borders and readable text colors separate the activities. Keyboard focus, sticky navigation clearance, enlarged text and dark colors keep their existing support. Existing trips, expenses, printing and suggested-time editing use the same storage paths.
