# Roam America v3.3 — 2026-09-20

This release implements the seven UX/UI refinement areas: mobile daily planning, navigation, homepage entry points, consistent state cards, practical destination summaries, visual/motion polish and startup performance. Planning remains local; no database was activated.

## Delivered

1. **Mobile daily planner.** Activities appear ahead of checklists and utility controls. State selection, day selection and Add activity share a sticky toolbar. Empty periods are compact buttons that open the form with the correct period selected. New activities receive focus and a selection highlight. Timing and reordering instructions sit in an expandable help section; actual schedule/access warnings remain visible.
2. **Mobile navigation.** The header uses compact, labeled controls with touch targets of at least 44 pixels. Comparison is available in the expanded mobile menu. Home and section links leave the planner correctly. The bottom navigation remains stable when input focus changes, so add/download taps are not intercepted by a newly appearing bar.
3. **Homepage entry points.** Search and the existing trip helper appear in the opening hero. A saved trip gets an early resume shortcut. Experience and season filters remain next to discovery. The layout accommodates all five interface languages.
4. **State cards and return navigation.** Card images and state names open a full guide through a real link. Quick view is a separate labeled action. Returning to discovery preserves state/place filters and scroll position, including browser Back.
5. **Practical destination summaries.** Interests, suggested duration, months/seasons and transport/gateway information sit below the cover. Dated access notices precede the longer guide. Add and Save are prominent; saving a place saves that place to the collection. Walking, setting and detailed access guidance remain available farther down the page.
6. **Visual and motion consistency.** Navy, warm cream and red styling carries through search, cards, guides and the planner. Save and activity feedback respect reduced motion. Rotating a landmark reuses the WebGL scene instead of rebuilding its resources. Button hover feedback keeps the hit target stationary, fixing repeated hover jitter near its edge.
7. **Startup work.** The atlas and 3D modules load near the map. Mobile uses a portrait hero crop with a matching responsive preload; generated guide pages preload their own cover. Vite derives a light photo index and deferred gallery metadata from the same editorial catalog. Source credits, captions and Studio draft previews remain intact. Language controls use native system fonts, avoiding an unnecessary Thai font download on the English homepage.

## Validation

- Production build and TypeScript check; content validation for 50 states, 150 places, 450 local photos and five languages.
- 114 regular browser checks, with failures corrected and all affected checks rerun successfully: Chromium desktop/mobile plus critical Firefox and WebKit journeys. Coverage includes accessibility, five-language layouts, navigation restoration, editing, exports, backups, comparison and Studio.
- Six production checks: deferred assets and photo credits, no-JavaScript pages and SEO, metadata navigation, offline plans/photos, five-language PDF output, and mocked optional account flows. No real emails or remote database calls.
- Local PGlite compatibility tests, formatting and Git whitespace checks.
- Production screenshots reviewed for desktop English and mobile Thai: home, full guide, daily planner, budget, backup and CA/NY/AZ landmark scenes. No page errors or horizontal overflow in these recorded journeys.

## Measured performance

Three cold-cache local Chromium runs at 390 × 844, DPR 3, 4× CPU slowdown, 1.6 Mbps download / 750 Kbps upload and 150 ms latency. Service workers were blocked to measure the application independently of offline-cache installation.

| Run | LCP     | FCP     | CLS | Resource transfer |
| --- | ------- | ------- | --- | ----------------- |
| 1   | 2.744 s | 1.492 s | 0   | 756,616 bytes     |
| 2   | 2.592 s | 1.212 s | 0   | 756,616 bytes     |
| 3   | 2.588 s | 1.404 s | 0   | 756,616 bytes     |

The recorded median LCP is 2.592 seconds, compared with 2.948 seconds in the v3.2 review. **The under-2.5-second target is still unmet.** These are local lab observations, not field Core Web Vitals or physical-phone measurements.

The selected mobile hero is 57,256 bytes instead of 169,206 bytes. The initial catalog is approximately 598 kB raw / 115 kB gzip, down from 909 kB / 175 kB; gallery metadata loads separately at about 63 kB gzip. The atlas and photo-details chunks were absent from every initial application load in the measurement. Offline-cache installation may subsequently fetch application assets for offline use.

Total measured transfer exceeds the v3.2 report's 587,205 bytes because the shorter homepage brings state-cover images into the browser's lazy-loading range earlier. The remaining large catalog still produces Vite's chunk-size warning; the warning limit has not been raised. Further payload reduction is needed to reliably get below 2.5 seconds under this profile.

Reproduce with `npm run build` and `node scripts/review-workspace.mjs`. Measurements and screenshots are written to ignored `artifacts/v3.3/`; `--screens-only` refreshes images while retaining the existing measurements.

Native-speaker sign-off, physical iPhone/Android testing and recruited usability sessions remain external review work. See [the review protocol](usability-check.md). A push runs CI; production hosting is not configured in this repository and must deploy the build separately.
