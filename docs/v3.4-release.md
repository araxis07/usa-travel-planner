# Roam America v3.4 — 2026-09-21

This release reduces mobile startup work and checks touch planning across Chromium and WebKit. No database was activated and no dependency was added.

## Changes

- Vite derives a deferred practical-details chunk from the existing editorial catalog. The initial catalog retains summaries, coordinates, planning filters and access advisories; full guides load access/stay guidance, official links, attribution and review metadata. Studio still uses complete draft profiles. Initial catalog size falls from about 598 kB raw / 115 kB gzip to 275 kB / 77 kB; the production build no longer emits the previous 500 kB chunk warning.
- Responsive photographs include a 640 px variant, with matching guide preloads. A 390 px, DPR 3 homepage selects this size for cards instead of 960 px. Offline saving and clearing include the new variant; the message limit accommodates all 450 photos with an original and three responsive sizes.
- Touch form controls on mobile/tablet widths use at least 16 px text. At widths up to 760 px and heights up to 500 px, the day toolbar scrolls with the page so it does not occupy most of the available form area. The bottom navigation remains stable when focus changes.
- New touch journeys cover five-language forms, short viewports, rotation, focused-field submission, reload persistence and dialog dismissal on iPhone Chromium, iPhone WebKit and Pixel Chromium profiles.

## Validation

- 120 regular browser checks passed, including existing desktop/mobile, Firefox, WebKit, accessibility, Studio and backup coverage.
- Six production checks passed: deferred chunks, responsive card images, five-language practical details, no-JavaScript pages and SEO, offline guides and all 36 photo assets for a selected state, PDF exports, offline message capacity and mocked account compatibility.
- TypeScript, production build, content validation, formatting and local PGlite compatibility checks passed. No tests connected to a remote database.
- Recorded production screenshots of English desktop and Thai mobile home, guides, planner, budget, backup and landmark scenes. Visually reviewed the mobile homepage and short/landscape forms. Recorded journeys had no page errors or horizontal overflow.

## Performance

Three cold-cache local Chromium runs at 390 × 844, DPR 3, 4× CPU slowdown, 1.6 Mbps download / 750 Kbps upload and 150 ms latency. Service workers were blocked, matching the v3.3 measurement profile. No builds or test suites ran during measurement.

| Run | LCP     | FCP     | CLS | Resource transfer |
| --- | ------- | ------- | --- | ----------------- |
| 1   | 2.424 s | 1.400 s | 0   | 613,019 bytes     |
| 2   | 2.416 s | 1.220 s | 0   | 613,019 bytes     |
| 3   | 2.420 s | 1.412 s | 0   | 613,019 bytes     |

Median LCP is **2.420 seconds**, down from v3.3's 2.592 seconds; all three runs meet the under-2.5-second lab target. Recorded resource transfer falls about **19%**, from 756,616 to 613,019 bytes. Atlas, photo-details and place-details chunks were absent from initial application loading. Service-worker installation may subsequently fetch application assets for offline use.

These are local lab measurements, not field Core Web Vitals or physical-phone results. Reproduce with `npm run build` followed by `node scripts/review-workspace.mjs`; ignored artifacts are written to `artifacts/v3.4/`. `--performance-only` records measurements; `--screens-only` refreshes screenshots while retaining measurements.
